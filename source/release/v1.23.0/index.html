Efficient Transformer Library - 1.23.0 Release Notes

  • Highlights
  • Model and Runtime Improvements
  • ONNX Export and Compatibility Fixes
  • CI and Repository Updates
  • Included Pull Requests

Efficient Transformer Library v1.23.0 adds DFlash speculative decoding, weight-free ONNX export for CausalLM models, and a more efficient KV-cache handoff for disaggregated serving. It also brings a set of blocking, MoE, ONNX export, VLM, and CI improvements.

These changes are available on the release/v1.23.0 branch and mainline.

Highlights

  • DFlash speculative decoding adds a block-diffusion draft model that predicts multiple tokens in parallel before target-model verification. The release includes the required transforms, runtime support, and example scripts.
  • Weight-free CausalLM export can build the ONNX graph without loading the complete checkpoint into host memory. The compiler can then read the weights directly from the original safetensors files.
  • KV-cache handoff for disaggregated serving lets prefill and decode sessions share host-side KV buffers, avoiding an extra Python-side copy between the two stages. Examples are included for GPT-OSS, Qwen3-MoE, Qwen3.5-MoE, Qwen3-VL-MoE, and Gemma4-MoE.
  • A common optimized MoE transform now handles shared MoE behavior and configuration across supported model families, including expert-parallel weight handling and export options.

Model and Runtime Improvements

  • Expanded blocking support for Qwen3-VL-MoE and Gemma4, including head-parallel, prefill, decode-MoE, batch-fold, and disaggregated execution paths.
  • Optimized Qwen3.5-MoE folded decode and improved generic blocked-attention performance for KV head-parallel decode and online prefill.
  • Added a separate vision_batch_size option for dual-QPC VLM compilation. Existing callers keep the previous behavior when the option is not provided.
  • Refactored GPT-OSS to use a per-layer dynamic cache while preserving compatibility with the legacy tuple-cache layout.
  • Moved GPT-OSS attention-mask preparation outside decoder subfunctions to avoid repeating layer-invariant ONNX work.
  • Added automatic compiler-dump generation when mdp_strategy="intersection" is used without an explicit dump path.
  • Updated hardware detection to identify AI200 devices from the NSP image variant reported by qaic-util.

ONNX Export and Compatibility Fixes

  • Preserved Hugging Face parameter names and FX source metadata in ONNX subfunction exports.
  • Moved constant ReduceSum axes into ONNX functions so model code can use regular reduction operations.
  • Fixed Gemma4 continuous-batching compilation with ONNX subfunctions.
  • Fixed Qwen3.5 dense and MoE subfunction export in the Conv1D fallback path.
  • Updated the Qwen3.5 Gated DeltaNet forward substitution.
  • Added clear errors for model classes and options that do not support weight-free export.
  • Fixed the continuous-batching QPC key mismatch between QEfficient and vLLM.
  • Stabilized Kimi K2.5 setup and CI coverage.
  • Updated NumPy support to >=2.2.6,<3 and protobuf to 6.33.6. Python 3.8 is no longer supported.

CI and Repository Updates

  • Added change-aware regression-test selection based on affected models and features.
  • Reworked CI model tiers, worker isolation, capability tracking, golden outputs, and report generation.
  • Improved CI stage names, LLM-based impact analysis, runtime-stage gating, and failure reporting.
  • Added repository migration workflows, pull-request templates, dependency updates, stale-issue handling, and a security policy.
  • Added the qeff-bug-fix development agent to skills_studio/agents.
  • Updated .gitignore for generated runtime files and local virtual environments.
